# PRODUCT BIBLE — AI Gift

**TASK-053.** Главный документ проекта.

На этот файл опираются все будущие изменения продукта, UX, архитектуры и приоритетов.  
Если фича конфликтует с PRODUCT BIBLE — побеждает PRODUCT BIBLE, пока явно не решено иначе.

---

## Позиционирование (одна строка)

**AI Gift** — сервис персональных подарков от идеи до вручения.

Это **не** магазин кружек.  
Это **не** фотосалон.  
Это **не** каталог сувениров.

Клиент описывает ситуацию — сервис подбирает, собирает и доводит заказ до вручения.  
Снаружи — единый бренд. Внутри — партнёры по технологиям, склад, доставка, owner-контроль.

---

## 1. Философия проекта

1. **Ситуация важнее SKU.** Человек приходит с «подарок папе рыбаку до 3000», а не с артикулом кружки.
2. **Готовый подарок важнее полки товаров.** На выходе — сцена / набор / решение, а не «выберите из 100 позиций».
3. **Технологии → товары.** Каталог строится вокруг того, что реально можно произвести у партнёров.
4. **Меньше трения до оплаты.** Регистрации до заказа нет. Аккаунт создаётся после первого заказа. Вход без пароля.
5. **Доверие и согласие.** Публикация отзывов и работ в галерею — только с явного opt-in (по умолчанию выкл. для галереи).
6. **Роли разделены.** Клиент, партнёр и владелец видят разное. PII клиента партнёру не отдаём. Партнёров клиенту не показываем.
7. **Повтор важнее разовой продажи.** Получатели, история подарков, «не дарить то же дважды», CRM в roadmap.
8. **AI — помощник, не цирк.** Сначала база знаний и правила; AI — fallback, когда знаний не хватает.

Короткий тест любой страницы: *если убрать логотип — это всё ещё «идея → готовый подарок»?* Если нет — мы сбились.

## 2. Что нельзя усложнять

Сводка из `NOT_TO_DO.md` и продуктового ядра. Ломать это — ломать бренд.

| Нельзя | Почему |
|--------|--------|
| Заставлять регистрироваться до заказа | Убивает первый заказ |
| Показывать 100 товаров на одном экране | Возвращает к каталогу, от которого уходим |
| Скрывать цену | Подарок привязан к бюджету и доверию |
| Заставлять ждать бессмысленные анимации | Теряем срочных клиентов (экспресс) |
| Усложнять оформление заказа | Checkout = контакты + доставка + отправить |
| Показывать партнёров клиенту | Клиент покупает бренд AI Gift |
| Передавать партнёру данные клиента | Безопасность и доверие |
| Добавлять функцию «просто потому что можно» | Только если улучшает путь пользователя |
| Делать вход с обязательным паролем | Passwordless — принятая модель |
| Публиковать работы/отзывы без согласия | Ломает доверие |
| Превращать первый экран в дашборд | Герой: бренд + запрос + действие |

**Правило:** новая фича обязана упрощать путь «ситуация → готовый подарок → вручение» или усиливать возврат/доверие. Иначе — не делаем.

## 3. Принципы UX

1. **Один смысл на секцию.** Один заголовок, одна задача, обычно одно действие.
2. **Бренд заметен.** На ключевых экранах бренд — не мелкая подпись в навбаре.
3. **Язык ситуации.** «Подарок маме», «срочно сегодня», а не «категория SKU-12».
4. **Цена и срок рядом с решением.** Не прячем итог и ожидание.
5. **Прогресс виден.** Статусы заказа понятны: от «Новая заявка» до «Доставлено».
6. **Конструктор, не каталог.** Добавить / убрать / заменить позиции, живой итог.
7. **Мобильный паритет.** Путь должен работать на телефоне без «версии для десктопа».
8. **Ошибки человеческим языком.** «Аккаунт появится после первого заказа», не технический жаргон.
9. **Карточки людей и история** помогают выбирать — не заставляют заполнять анкету до покупки.
10. **Социальное доказательство без давления.** Отзывы и галерея — ниже героя, только публичное с согласия.

## 4. Как думает пользователь

Типичный внутренний монолог:

1. «Не знаю, что подарить.»
2. «Нужно к дате / срочно.»
3. «Есть бюджет.»
4. «Хочу, чтобы выглядело лично, не как с полки.»
5. «Боюсь заказать ерунду / то же, что в прошлом году.»
6. «Где заказать, чтобы не бегать по типографиям?»
7. «Как объяснить друзьям, где взял?»

Что пользователь **не** хочет:

- выбирать между десятками одинаковых кружек;
- разбираться в технологиях печати;
- регистрироваться «на всякий случай»;
- звонить трём подрядчикам;
- вспоминать, что уже дарил.

Что мы даём вместо этого:

- запрос своими словами / экспресс / повод / карточка получателя;
- готовые наборы и конструктор;
- история подарков «не повторять»;
- один бренд до вручения.

## 5. Полный путь клиента

```
Приход → Запрос / экспресс / повод / получатель
      → Идеи и готовый набор (конструктор)
      → Оформление заявки (без регистрации)
      → Подтверждение и производство
      → Доставка / самовывоз
      → Доставлено
      → (опционально) отзыв, работа в галерею, история у получателя
      → Возврат на следующий повод
```

### Детали

| Этап | Что происходит |
|------|----------------|
| Главная | Бренд, поиск «что подарить?», выбор получателя, экспресс, поводы, наборы, галерея, отзывы |
| Подбор | База знаний (+ AI fallback), конструктор, «уже дарили» учитывается |
| Checkout | Имя, телефон, опционально email, доставка, комментарий → заявка |
| Аккаунт | Создаётся автоматически после первого заказа; вход SMS / Google / Email |
| После | Статусы, отзыв (после «Доставлено»), публикация в галерею (opt-in), история подарков |

Клиент **не** видит: маржу, внутренних партнёров, чужие заказы, складскую кухню.

---

## 6. Полный путь владельца

Владелец — полный контроль бизнеса (`/owner`).

```
Вход (owner) → Дашборд
  → Клиенты и заказы (все статусы, поиск, фильтры)
  → Партнёры (сеть, возможности, статусы)
  → Финансы (выручка, расходы, прибыль)
  → Склад и закупки
  → Доставка
  → Цены / продукты / база знаний / настройки AI
  → История и статистика
```

### Принципы owner-пути

- Видит всё, что нужно для управления: клиенты, партнёры, деньги, статусы.
- Может менять статусы и контролировать срывы сроков.
- Не смешивает свой кабинет с клиентским UX на витрине.

---

## 7. Полный путь партнёра

Партнёр — исполнитель по технологиям (`/partner`).

```
Вход (логин партнёра) → Только свои заказы
  → Что сделать, количество, макет, срок, комментарий к производству
  → Статусы: Получен → В работе → Готов → Выдан курьеру
  → Синхронизация с админским пайплайном
```

### Жёсткие границы

- **Видит:** производственные задачи.
- **Не видит:** телефон/адрес клиента как PII-витрину, цены клиента, маржу, чужих партнёров, чужие заказы.
- Клиенту партнёр **не** показывается как отдельный бренд.

Публичная страница `/partners` — витрина возможностей сети для B2B/прозрачности модели; операционный кабинет — отдельный контур.

## 8. Монетизация

Зарабатываем на решении ситуации, не только на «одной кружке».

| Источник | Смысл |
|----------|--------|
| Персональные изделия | Печать, текстиль, гравировка, вышивка, UV и др. |
| Подарочные наборы | Основное + упаковка + открытка + дополнения |
| Корпоратив | Welcome-box, мерч, тиражи, подарки сотрудникам |
| Дополнения | Чай, кофе, шоколад, свечи, рамки… |
| Упаковка и открытки | Отдельные позиции, рост среднего чека |
| Комиссия / маржа с партнёров | Производство снаружи, бренд и заказ внутри |

**Экономическая логика:** средний чек растёт через набор и дополнения; масштаб — через корпоратив и города. В будущем — цветы/шары в наборах, собственное производство.

Онлайн-оплата — этап усиления продукта (Roadmap), не блокер смысла MVP-заявки.

## 9. Roadmap

Актуальная карта — `08_Roadmap.md`. Здесь — сжатый канон приоритетов.

### Этап 1 — MVP (Красноярск)

Партнёры и база технологий/цен/сроков → простой путь поиск → варианты → заявка → первый заказ вручную.

### Этап 2 — Усиление

Больше стилей, автосбор наборов, онлайн-оплата, расширение каталога, корпоративные заявки.

### Этап 3 — Масштаб

Кабинеты партнёров (углубление), автоназначение по технологиям, новые города, цветы и шары.

### Отложено (явно)

- **TASK-046 CRM клиентов** — история, любимые товары, поводы, ДР, годовщины, напоминания, повторные продажи. *Не сейчас* — после стабилизации заказов, склада, доставки и Owner.

### Уже заложено в продукте (каркас)

Passwordless auth, получатели и история подарков, отзывы, галерея вдохновения, пайплайн заказов, partner/owner, склад/закупки/доставка — наращивать глубину, не ломая философию §1–2.

## 10. Риски

Операционные вопросы из `RISKS.md` — обязательный чеклист. На каждый риск нужна процедура (даже ручная на старте).

| Риск | Направление ответа |
|------|-------------------|
| Партнёр сорвал срок | Эскалация owner, запасной партнёр, честный статус клиенту, компенсация/ускорение |
| Клиент отказался | Правила отмены до/после производства, фиксация в заказе |
| Макет нарушает авторские права | Отказ в печати, запрос другого контента, ответственность за загруженные материалы |
| ИИ сгенерировал неподходящее | Модерация / ручная проверка до производства, фильтры, кнопка «другое» |
| Нет нужного товара у партнёра | Замена из доступных технологий, другой партнёр, согласование с клиентом |
| В одном заказе 3 производства | Разбиение на подзаказы, единый статус для клиента, сводный контроль owner |

Дополнительно продуктовые риски:

- скатиться в каталог SKU;
- утечка PII к партнёру;
- публикация без согласия;
- перегруз первого экрана;
- AI без базы знаний (дорого и нестабильно).

## 11. Почему пользователь вернётся

1. Поводы повторяются (ДР, праздники, «просто так»).
2. Аккаунт без боли — вход по SMS/коду, без обязательной регистрации заранее.
3. **Получатели** и **история подарков** — помним вкусы и не дарим то же дважды.
4. Галерея и «Хочу такой же» — быстрый повтор идеи.
5. Экспресс — когда снова срочно.
6. CRM-напоминания (Roadmap) — сервис сам напомнит о дате.

Возврат = повторяющаяся жизненная задача, не подписка ради подписки.

---

## 12. Почему пользователь расскажет друзьям

1. Вау при вручении — личный подарок хочется показать.
2. Простой ответ: «Закажи в AI Gift» — один бренд, без квеста по типографиям.
3. Ссылка на галерею / отзывы — совет конкретный.
4. «Хочу такой же» — совет сразу становится заказом друга.
5. Корпоратив и семья размножают сарафан.

Сарафан работает, когда совет **воспроизводим**.

---

## 13. Что делает проект уникальным

| Обычный рынок | AI Gift |
|---------------|---------|
| Каталог товаров | Готовый подарок под ситуацию |
| Клиент сам ищет | Подбор (знания → AI fallback) |
| Один SKU | Набор + сцена + дополнения |
| Видны цеха / «типография» | Единый бренд до вручения |
| Нет памяти о людях | Получатели + история «не повторять» |
| Регистрация до покупки | Аккаунт после заказа, passwordless |
| Либо магазин, либо производство | Витрина + сеть технологий + owner-контроль |

**Уникальность в одной фразе:**  
мы продаём **спокойствие «я знаю, что подарить и это доедет вовремя»**, а не полку сувениров.
