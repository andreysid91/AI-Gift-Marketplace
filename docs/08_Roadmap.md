## TASK-046 — CRM клиентов (не сейчас · Roadmap)

> Отложено. Не входит в текущий спринт / MVP-реализацию.
> Делать после стабилизации заказов, склада, доставки и Owner Dashboard.

### Цель

Личная CRM по клиентам для повторных продаж и напоминаний о важных датах.

### Возможности

- История заказов клиента

- Дни рождения
- Годовщины

### Зависимости

- Профили клиентов из заказов (уже частично есть в Owner → Клиенты)
- База знаний поводов (`occasions`)

### Критерии готовности (когда дойдём)

1. Карточка клиента с историей заказов
2. Сохранённые любимые товары и частые поводы
3. Календарь ДР / годовщин
4. Очередь напоминаний
5. Сценарий повторной продажи из напоминания → конструктор / готовый набор

## TASK-054 — Коллективный подарок «Скинуться» (не сейчас · Roadmap)

> Отложено. Связано с Gift Profile / Wish List. Не реализовывать в текущем спринте.

### Цель

Несколько друзей скидываются на один пункт wish list (или на выбранный подарок с публичного профиля).

### Концепция

1. Владелец профиля (или даритель) открывает сбор на wish / товар.
2. Публичная или закрытая ссылка на «копилку».
3. Участники видят цель, собранную сумму, дедлайн, список (опционально анонимных) взносов.
4. Когда сумма достигнута — заказ оформляется через AI Gift (или вручную owner), wish помечается «подарено».
5. Если не добрали — возврат взносов / перенос / смена цели (правила заранее).

### Что нужно продумать до реализации

- Платежи и холдирование / эскроу (или ручной MVP без онлайн-оплаты)
- Минимальный взнос и анонимность
- Кто получает подарок и куда доставка
- Отмена и недобор
- Связь с приватностью Gift Profile
- Уведомления участникам

### Зависимости

- Gift Profile + Wish List (уже есть каркас)
- Онлайн-оплата (Этап 2)
- Статусы заказа и «что уже подарили»

### Критерии готовности (когда дойдём)

1. Создать сбор с wish list
2. Ссылка для друзей
3. Учёт взносов и прогресс
4. Финализация → заказ / fulfilled wish
5. Правила недобора задокументированы в RISKS / Business Rules
