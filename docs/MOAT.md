# MOAT — Конкурентные преимущества AI Gift

Один из самых важных документов проекта.

**MOAT** здесь — не лозунг, а карта того, *почему нас выбирают, почему остаются, почему советуют*, и *что конкурентам трудно скопировать быстро и целиком*.

Связан с `PRODUCT_BIBLE.md`: BIBLE задаёт правила игры, MOAT объясняет, **за счёт чего мы выигрываем**.

---

## Как читать этот документ

- **Уже работает / заложено** — то, что усиливает ров сегодня.
- **Усиливается со временем** — данные, сеть, привычка, бренд.
- **Roadmap** — ещё не построено, но логично добивает ров (например CRM).

Конкурент может скопировать одну кнопку.  
Скопировать **систему** «ситуация → готовый подарок → память о людях → производство под брендом → возврат» — уже другая цена.

# 1. Почему пользователь выберет именно нас

## 1.1. Боль, которую мы закрываем лучше рынка

Пользователь редко хочет «купить кружку».  
Он хочет **закрыть ситуацию**: день рождения, срочно сегодня, коллеге, жене на годовщину, папе-рыбаку до 3000.

Обычные альтернативы:

| Альтернатива | Почему проигрывает нам в момент выбора |
|--------------|----------------------------------------|
| Маркетплейс / сувенирный магазин | Каталог SKU, сам ищи, сам собирай смысл |
| Фотосалон / типография | Нужно знать технологию, макет, сроки; «не про подарок» |
| Самому собрать набор | Время, логистика, риск «не успею» |
| Спросить друзей | Нет воспроизводимого действия «заказать такое же» |
| «Просто цветы / шоколад» | Дешево по смыслу, не персонально |

**Наш ответ:** опиши ситуацию (или выбери повод / экспресс / карточку человека) → получи готовый вариант с ценой → доработай конструктором → оформи заявку без регистрации.

## 1.2. Конкретные причины выбора «именно AI Gift»

1. **Говорим на языке ситуации**, а не артикулов.  
   «Подарок маме», «папе рыбаку до 3000», «срочно сегодня».

2. **Видят результат сразу** — набор / сцена / итог, а не бесконечная полка.

3. **Экспресс-путь** — когда времени нет: 3 вопроса → готовые наборы.

4. **Поводы и готовые наборы** — не нужно «придумать с нуля».

5. **Конструктор без страха** — можно убрать/добавить, цена живая.

6. **Цена не спрятана** — бюджет уважается.

7. **Нет регистрации до покупки** — порог входа минимальный.

8. **Единый бренд до вручения** — не нужно выбирать между тремя цехами.

9. **Память о получателе** (карточки людей) — подбор точнее с первого осознанного визита после заказа.

10. **История подарков** — обещание «не подарим то же самое снова» снимает сильный страх.

11. **Социальное доказательство** — отзывы «счастливые клиенты», галерея вдохновения, «заказали N раз».

12. **Понятный следующий шаг** — «Хочу такой же» из галереи.

## 1.3. Формула выбора

> Выбирают нас, когда важнее **спокойствие «я знаю, что дарить и это успеет»**, чем самый дешёвый SKU на маркетплейсе.

# 2. Почему пользователь вернётся

Возврат в подарках — не «открыть приложение каждый день».  
Возврат — **следующий повод**. Наш ров = стать дефолтным ответом на следующий повод.

## 2.1. Структурные причины возврата

1. **Поводы не заканчиваются**  
   ДР, 8 марта, 23 февраля, свадьбы, учителя, коллеги, «просто так», корпоратив.

2. **Аккаунт без трения**  
   Появился после первого заказа; вход SMS / Google / Email без пароля. Легко зайти снова.

3. **Карточки получателей**  
   Мама, папа, жена — вкусы, размеры, напитки уже сохранены. Не начинать с нуля.

4. **История подарков**  
   Дата, что дарили, цена, фото, отзыв. Главный хук: *никогда не дарить одно и то же дважды*.

5. **Подбор учитывает историю**  
   Уже подаренное не предлагается / помечается — сервис «помнит за меня».

6. **Галерея и «Хочу такой же»**  
   Быстрый повтор чужой или своей успешной идеи.

7. **Экспресс**  
   В стрессе возвращаются туда, где уже получалось быстро.

8. **CRM-напоминания (Roadmap)**  
   Сервис сам напомнит о ДР / годовщине → повторная продажа из сигнала, не из памяти.

## 2.2. Эмоциональные причины возврата

- «В прошлый раз выручили.»
- «Там уже знают, кому я дарю.»
- «Не стыдно за подарок.»
- «Не надо снова гуглить типографии.»

## 2.3. Метрики рва возврата (на что смотреть)

- Доля повторных заказов на одного клиента / получателя  
- Использование карточек получателей при втором заказе  
- Клики «Подобрать» из карточки человека  
- Срабатывания «уже дарили» (как часто система спасает от дубля)  
- Возвраты через экспресс vs через поиск

# 3. Почему пользователь расскажет друзьям

Сарафан в подарках сильный: подарок — социальный объект.  
Но совет должен быть **конкретным и воспроизводимым**.

## 3.1. Триггеры рассказа

1. **Вау при вручении**  
   Персональный предмет + набор + упаковка → хочется показать фото в чат.

2. **Простой ответ на «где взял?»**  
   Один бренд: «В AI Gift» — не «искал у пяти ребят».

3. **Ссылка на галерею / отзыв**  
   Можно скинуть: «посмотри, что люди дарят».

4. **«Хочу такой же»**  
   Друг не только слышит совет — сразу повторяет заказ.

5. **Снятие стыда «я опять ничего не придумал»**  
   Люди хвалятся не магазином, а тем, что *наконец нашли способ*.

6. **Корпоратив и семья**  
   Один удачный welcome-box / ДР → запросы от коллег и родственников.

## 3.2. Что усиливает сарафан продуктово

- Публичные работы только с согласия (доверие → охотнее делятся)  
- Красивые карточки в галерее (превью, повод, соцметрики)  
- Отзывы со звёздами и фото готового подарка  
- Понятный первый экран у друга (не дашборд)

## 3.3. Анти-паттерны (ломают сарафан)

- Стыдно показать сайт (каталог «как у всех»)  
- Друг не может повторить путь за 1–2 минуты  
- Обещали персональное — вышло шаблонно

# 4. Что конкурентам будет сложно повторить

Копировать можно UI. Сложно повторить **связку**.

## 4.1. Слои рва (от быстрого копирования → к медленному)

### A. Продуктовая модель (средне сложно)

- Не каталог, а **ситуация → готовый подарок**  
- Knowledge Engine + AI только как fallback  
- Конструктор наборов с живым итогом  
- Экспресс + поводы + готовые сеты  

Конкурент-маркетплейс *может* добавить «AI-поиск», но обычно останется витриной SKU.

### B. Операционная модель (сложно)

- Единый бренд снаружи + **сеть технологий** внутри  
- Пайплайн статусов до вручения  
- Партнёр видит производство, **не** видит клиента и маржу  
- Owner видит деньги, склад, закупки, всех партнёров  
- Контроль качества на стороне сервиса, не «клиент сам с цехом»

Это требует процессов, договоров, дисциплины данных — не одной фичи.

### C. Данные о людях и подарках (очень сложно со временем)

- Карточки получателей (вкусы, размеры, ДР…)  
- История подарков с составом → антидубли  
- Связка заказ ↔ человек ↔ что уже дарили  
- Позже: CRM-календарь поводов  

Чем больше заказов — тем умнее подбор **именно у нас**. Новый конкурент стартует с пустой памятью.

### D. Социально-контентный слой (усиливается)

- Галерея вдохновения с opt-in  
- Метрики лайков / просмотров / «заказали»  
- Отзывы после доставки с фото  

Контент пользователей + доверие к публикации копируются медленно.

### E. Бренд «спокойствия» (самый медленный)

Позиция: *не магазин кружек, а сервис от идеи до вручения*.  
Пока конкуренты продают изделия, мы продаём **снятие тревоги**. Бренд копируют годами.

## 4.2. Что *не* считать рвом

- «У нас есть AI» (есть у многих)  
- «Красивый сайт» (воспроизводимо)  
- «Есть кружки и футболки» (коммодити)  

Ров — в **системе смысла + памяти + исполнения под одним брендом**.

## 4.3. Защита от «просто скопируют экран»

Даже при копировании UI без:

- базы знаний, завязанной на реальные технологии партнёров;
- истории получателей;
- партнёрских границ PII;
- привычки клиентов возвращаться;

…копия останется пустой оболочкой.

# 5. Какие функции создают эмоциональную привязанность

Эмоциональная привязанность = «этот сервис *про моих людей*», не «ещё один магазин».

| Функция | Какая эмоция | Почему цепляет |
|---------|--------------|----------------|
| Карточки получателей | Забота, близость | «Сервис знает маму так же, как я» |
| История подарков + фото + отзыв | Гордость, тепло | Альбом отношений, не чек |
| «Не дарить то же дважды» | Спокойствие, уважение | Снимает страх выглядеть невнимательным |
| Персональный дизайн / фото на изделии | Уникальность | «Такого ни у кого нет» |
| Готовый красивый набор | Радость предвкушения | Видно вау до покупки |
| Экспресс в стрессе | Облегчение | «Выручили, когда горело» |
| Отзыв после вручения | Завершённость | История получила финал |
| Галерея (свои работы) | Признание | Мой вкус видят другие (если я разрешил) |
| «Хочу такой же» | Сопричастность | Чужой успех стал моим действием |
| Passwordless / без регистрации до заказа | Уважение ко времени | «Меня не доят формой» |
| Понятные статусы до «Доставлено» | Контроль тревоги | Подарок к дате — нервы |

**Ядро привязанности:** получатель + история + антидубль.  
Это превращает разовую покупку в **отношения с сервисом вокруг людей, которых любят**.

# 6. Какие функции увеличивают средний чек

Средний чек растёт не «накручиванием», а логикой *лучшего подарка*.

| Функция | Как поднимает чек |
|---------|-------------------|
| Готовые подарочные наборы | Базовый товар + упаковка + дополнения пакетом |
| Конструктор (добавить позицию) | Легко докинуть шоколад / чай / свечу / открытку |
| Рекомендации дополнений из базы знаний | Релевантный апселл, не случайный |
| Упаковка как отдельная ценность | «Красиво вручить» = отдельная строка |
| Открытка / персональный текст | Дешёвая для нас, ценная для клиента строка |
| Бюджетные ветки «до 3000 / 5000 / wow» | Честно тянет в более высокий сегмент без стыда |
| Корпоративные наборы / тиражи | Объём × позиция |
| «Хочу такой же» из сильных работ | Повтор успешных дорогих сценариев |
| Экспресс «нужно сегодня» | Премия за скорость (когда модель позволит) |
| Доставка курьером / срочные методы | Доп. услуга к заказу |
| Наборы «под повод» (свадьба, 8 марта…) | Готовность платить за попадание в момент |

**Принцип:** апселл должен усиливать *ощущение подарка*, а не выглядеть жадностью.  
Тогда рост чека = рост ценности, и это тоже ров (доверие к рекомендациям).

# 7. Какие функции уменьшают количество отказов

Отказ = ушёл с поиска, бросил конструктор, не отправил заявку, отменил после заявки.

## 7.1. До заявки (конверсия в заказ)

| Функция | Какой отказ снимает |
|---------|---------------------|
| Поиск на языке ситуации | «Не понимаю, с чего начать» |
| Подсказки / поводы / экспресс | Паралич выбора |
| Готовые наборы | «Слишком сложно собрать» |
| Живая цена в конструкторе | Страх сюрприза по деньгам |
| Видимые сроки / «сегодня?» | Страх не успеть к дате |
| Без регистрации до checkout | Бросок на форме логина |
| Короткий checkout | Бросок на длинной анкете |
| Карточка получателя (автозаполнение смысла) | «Снова описывать с нуля» |
| Антидубль «уже дарили» | Сомнение «а вдруг повтор» → уход «подумать» |
| AI только как fallback | Долгое ожидание / бред генерации на каждом шаге |
| Честный «свяжемся и подтвердим» на MVP | Страх мгновенного списания без диалога |

## 7.2. После заявки (отмена / разочарование)

| Функция | Какой отказ снимает |
|---------|---------------------|
| Статусы пайплайна | Тревога «пропали» → отмена |
| Связь менеджера / подтверждение | Неясность состава и срока |
| Замена при отсутствии товара у партнёра (процесс) | Отказ «нет в наличии» |
| Модерация спорных макетов | Отказ из-за прав / контента |
| Эскалация при срыве срока партнёром | Отказ из-за опоздания |
| Разделение заказа на производства (операционно) | Хаос → клиент выходит |

## 7.3. Продуктовый принцип против отказов

Каждый экран должен отвечать на один страх:  
*успею? попадёт? не стыдно? не обманут по цене? не заставят мучиться формой?*

# 8. Какие функции помогают владельцу бизнеса

Owner — мозг и нервная система сети (`/owner` и связанные контуры).

| Функция / контур | Польза владельцу |
|------------------|------------------|
| Единый поток заказов и статусов | Контроль от заявки до вручения |
| Клиенты в одном месте | База для повторных продаж и CRM |
| Партнёры: возможности, сроки, статусы | Управление сетью, а не хаосом чатов |
| Финансы: выручка, расходы, прибыль | Понимание, жив ли бизнес |
| Склад + авто-сигналы «нужно купить» | Меньше срывов из-за расходников |
| Закупки со статусами | Замкнутый контур пополнения |
| Доставка: методы, трек, стоимость | Прозрачность последней мили |
| Цены / продукты / база знаний | Рычаги маржи и качества подбора |
| Настройки AI | Контроль затрат и качества fallback |
| Поиск и фильтры по заказам | Операционная скорость |
| Разделение ролей (клиент ≠ партнёр ≠ owner) | Безопасность маржи и данных |
| Отзывы и галерея (как сигнал качества) | Что реально заходит людям |
| История подарков у получателей (агрегируемо позже) | Инсайты для ассортимента |

**Стратегическая польза:** владелец масштабирует **бренд и процесс**, не обязан лично быть каждой типографией.

# 9. Какие функции помогают партнёрам

Партнёр остаётся, если ему **понятно, выгодно и не токсично** работать.

| Функция | Польза партнёру |
|---------|-----------------|
| Кабинет только со своими заказами | Фокус, без чужого шума |
| Чёткое ТЗ: что сделать, qty, макет, срок, комментарий | Меньше бесконечных уточнений |
| Статусы производства (получен → … → курьеру) | Прозрачный прогресс без звонков «ну как?» |
| Синхронизация с админским пайплайном | Меньше двойного учёта |
| **Нет** клиентского PII в фокусе кабинета | Меньше юридической и этической нагрузки |
| **Нет** чужих заказов и маржи | Доверие к площадке |
| Поток заказов от бренда | Маркетинг делает сервис, партнёр делает изделие |
| Технологии как язык заказа | Попадают заказы, которые реально умеют |
| Публичная/внутренняя карта возможностей | Правильное назначение работ |

**В чём ров для партнёров:** стабильный поток + чистый процесс > разовый заказ из соцсетей с хаосом в мессенджере.

# 10. Какие функции можно монетизировать отдельно

Не всё должно быть «в цене кружки». Часть ценности — отдельные продукты/тарифы.

## 10.1. Уже логичные отдельные линии

| Что | Как монетизировать |
|-----|--------------------|
| Срочность / экспресс «сегодня» | Наценка за lead time |
| Премиум-доставка / курьер к часу | Отдельная услуга |
| Корпоративные тиражи и welcome-box | B2B-прайс, менеджерский сервис |
| Дизайн «под ключ» / несколько стилей | Пакеты дизайна |
| Физическая премиум-упаковка | Отдельная SKU-линейка |
| Открытка + персональный текст | Низкая себестоимость, отдельная цена |
| Фотопечать большого формата / холсты | Премиум-сегмент изделий |

## 10.2. Подписочные / сервисные (после CRM)

| Что | Модель |
|-----|--------|
| Напоминания о ДР / годовщинах + подбор | Подписка «не забудь» или % с повторных |
| Семейный кабинет получателей | Family plan |
| Корпоративный портал (сотрудники, даты, лимиты) | SaaS для HR + маржа на тиражах |

## 10.3. B2B и сеть

| Что | Модель |
|-----|--------|
| Комиссия с партнёров | % с выполненного |
| Приоритет в назначении заказов | Платный статус партнёра |
| White-label / франшиза города | Лицензия + роялти (далеко) |
| Доступ к агрегированной статистике спроса (обезличенной) | Для крупных партнёров |

## 10.4. Контент и внимание

| Что | Модель |
|-----|--------|
| Продвижение работы в галерее | Boost (осторожно, без убийства доверия) |
| Брендированные корпоративные витрины идей | Платные подборки для компаний |

## 10.5. Чего не монетизировать отдельно (чтобы не убить ров)

- Базовую память «не дарить то же дважды» для обычного клиента — это доверие, не paywall  
- Согласие на публикацию — не продавать «приватность»  
- Сам факт входа без пароля / без регистрации до заказа

# Сводка: где наш настоящий MOAT

```
Ситуация (не SKU)
    + готовый подарок / набор / экспресс
    + память о людях и истории подарков
    + доверие (opt-in, без лишнего трения)
    + исполнение под одним брендом (партнёры скрыты)
    + owner-контроль операций и денег
    → возврат на следующий повод
    → сарафан («закажи там же»)
    → данные, которые новому конкуренту не купить за неделю
```

## Приоритет усиления рва (практически)

1. Не ломать философию «ситуация → подарок» (BIBLE).  
2. Наращивать **данные получателей и историй**.  
3. Держать **качество исполнения и сроков** (иначе бренд «спокойствия» умрёт).  
4. Растить **галерею и отзывы** как социальный слой.  
5. Добить **CRM-напоминания** — превратить поводы в системный возврат.  
6. Масштабировать **сеть партнёров по технологиям** без утечки PII.
